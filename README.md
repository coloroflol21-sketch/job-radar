# Job Radar

Мониторинг новых вакансий с уведомлениями в Telegram и отправкой откликов прямо из чата.
Каждые полчаса опрашивает открытое API «Работа в России», отбирает подходящее по зарплате
и стоп-словам, отбрасывает уже виденное и присылает дайджест. Отклик отправляется командой
`/apply A1` с текстом письма — бот сам находит адрес работодателя и отправляет письмо по SMTP.

Работает без сервера и без платных подписок: расписание держит GitHub Actions, состояние
хранится в самом репозитории. Дайджест-сценарий продублирован как workflow для n8n.

![тесты](https://img.shields.io/badge/tests-116%20passing-brightgreen)

## Зачем

Открывать сайты вакансий каждый день — рутина, а хорошие предложения закрываются за пару суток.
Радар делает это сам, присылает только то, что раньше не показывал, и позволяет откликнуться
из того же чата, не открывая ни сайт, ни почтовый клиент.

## Что внутри

| `src/telegram.js` | дайджест, отправка сообщений, чтение команд |
| `src/inbox.js` | цикл обработки команд из чата |
| `src/commands.js` | разбор команд и проверка отклика перед отправкой |
| `src/handler.js` | исполнение команд и формирование ответов |
| `src/catalog.js` | короткие коды вакансий (`A1`, `B3`) для команд |
| `src/mailer.js` | письмо-отклик и отправка по SMTP |
| `src/state.js` | история, каталог, журнал откликов между запусками |

Источник — [opendata.trudvsem.ru](https://opendata.trudvsem.ru), государственный портал «Работа
в России». Выбран потому, что не требует ни ключа, ни регистрации, ни одобрения приложения:
hh.ru закрыл поиск вакансий за OAuth и отдаёт `403` анонимным клиентам.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/list` | вакансии, доступные для отклика, с их кодами |
| `/preview A1` | контакты и адрес, куда уйдёт отклик |
| `/apply A1` + текст письма с новой строки | отправить отклик |
| `/sent` | история отправленных откликов |
| `/help` | справка |

Отклик пишется одним сообщением: первая строка — команда, дальше текст письма.

```
/apply A1
Здравствуйте! Заинтересовала вакансия Python-разработчика.
Три года пишу на Python, опыт с Django и PostgreSQL. Резюме прилагаю ниже.
```

Бот отвечает не мгновенно. Он читает команды при очередном запуске по расписанию, то есть
в среднем через 15 минут. Telegram хранит непрочитанные сообщения 24 часа, поэтому команда,
отправленная ночью, выполнится утром и не потеряется.

## Как запустить локально

Нужен Node.js 20 или новее.

```bash
npm ci
npm test              # 116 тестов
npm run dry-run       # показать найденное в консоли, ничего не отправляя
```

Для реальной работы понадобятся токен бота и id чата:

```bash
export TELEGRAM_BOT_TOKEN="123456:ABC..."
export TELEGRAM_CHAT_ID="123456789"
npm start
```

Отправка откликов требует ещё и доступа к почте (`SMTP_USER`, `SMTP_PASSWORD`). Без них
поиск вакансий работает как обычно, а `/apply` ответит, что почта не настроена.

## Подключение Telegram-бота

1. Напишите [@BotFather](https://t.me/BotFather), отправьте `/newbot` и следуйте подсказкам.
   В ответ придёт токен вида `123456:ABC-DEF...`.
2. Напишите своему боту любое сообщение — без этого он не имеет права писать вам первым.
3. Узнайте id чата: откройте `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
   и найдите `"chat":{"id":...}`.

Токен — это пароль от бота. Держите его в секретах GitHub или переменных окружения,
никогда не коммитьте в код.

## Настройка почты для откликов

Письма уходят с вашего адреса через SMTP. Обычный пароль от почты не подойдёт —
нужен **пароль приложения**, отдельный пароль для программ.

| Провайдер | `SMTP_HOST` | `SMTP_PORT` | Где взять пароль приложения |
| --- | --- | --- | --- |
| Яндекс | `smtp.yandex.ru` | `465` | Яндекс ID → Пароли приложений → Почта |
| Mail.ru | `smtp.mail.ru` | `465` | Настройки → Пароли для внешних приложений |
| Gmail | `smtp.gmail.com` | `465` | Google Account → App Passwords |

Письма уходят с адреса из `SMTP_USER`. Если нужно отправлять с другого адреса или подписью
вида `Имя Фамилия <me@example.com>`, задайте `SMTP_FROM` — ответы всё равно будут приходить
на `SMTP_USER`.

Для Gmail пароль приложения доступен только при включённой двухэтапной аутентификации.
У всех провайдеров пароль показывается один раз — сохраните его сразу, иначе придётся
создавать новый. Отзывается он там же, независимо от основного пароля.

Для поиска работы в России удобнее Яндекс или Mail.ru: настройка короче, письма с их
адресов реже попадают в спам у российских работодателей.

## Запуск по расписанию в GitHub Actions

1. Создайте репозиторий и загрузите в него проект.
2. В настройках репозитория откройте **Settings → Secrets and variables → Actions**
   и добавьте секреты: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
   а для откликов ещё `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_HOST`, `SMTP_PORT`.
3. Разрешите workflow писать в репозиторий: **Settings → Actions → General →
   Workflow permissions → Read and write permissions**. Это нужно, чтобы радар
   коммитил `state/state.json` и не присылал одни и те же вакансии повторно.
4. На вкладке **Actions** выберите **Job Radar → Run workflow**. Для первой
   проверки поставьте галочку `dry_run` — вакансии появятся в логе без отправки в чат.

Дальше запуск идёт сам по cron. Расписание в `job-radar.yml` задано в UTC:
`17,47 4-19 * * *` — каждые полчаса с 07:00 до 22:00 по Москве. Это же значение задаёт
задержку ответа бота на команды, поэтому чаще получается отзывчивее, но дороже по квоте:
960 минут в месяц при лимите 2000 у приватного репозитория.

GitHub может отключить cron в репозитории, где 60 дней не было активности — достаточно
зайти и запустить workflow вручную. Также cron на бесплатном тарифе иногда стартует
с задержкой в несколько минут, для этой задачи это неважно.

## Вариант на n8n

Файл `n8n/job-radar.workflow.json` импортируется через **Workflows → Import from File**
и повторяет ту же логику из пяти нод: расписание → сборка запросов → HTTP-запрос →
отбор и оформление → отправка в Telegram.

Токен и id чата берутся из переменных окружения n8n — задайте `TELEGRAM_BOT_TOKEN`
и `TELEGRAM_CHAT_ID` перед запуском. В self-hosted n8n доступ к `$env` из выражений
включается переменной `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`. Если правило запрещено
политикой вашей установки, замените в ноде «Отправить в Telegram» подстановку `$env`
на обычные Telegram-креды n8n.

Историю отправленного n8n держит в `$getWorkflowStaticData('global')`, поэтому файл
состояния здесь не нужен.

Команды и отклики в версию для n8n не вошли, и это ограничение самого n8n, а не недоделка.
Нода Telegram Trigger умеет работать только через `setWebhook`, то есть требует публичный
HTTPS-адрес, на который Telegram будет отправлять сообщения. Локальный n8n такого адреса
не имеет, а `getUpdates` и webhook по правилам Telegram взаимоисключающие. Поэтому
интерактивная часть живёт в скрипте, а n8n отвечает за дайджест.

Логика нод покрыта тестами (`test/n8n-workflow.test.js`): они исполняют код прямо из JSON
workflow, так что версия для n8n не может разойтись с версией для Actions незамеченной.

## Настройка под себя

Всё, что меняется без правки кода, лежит в `config.json`:

```json
{
  "queries": [{ "text": "python", "region": "7700000000" }],
  "filters": {
    "minSalary": 80000,
    "excludeKeywords": ["вахта", "курьер"],
    "requireSalary": false,
    "maxAgeDays": 3
  },
  "limits": { "perQuery": 100, "maxNotificationsPerRun": 12 }
}
```

- `queries` — поисковые запросы; `region` можно не указывать, тогда поиск идёт по всей стране.
  Код региона — это код ОКТМО: две цифры региона и восемь нулей. Проверенные значения:

  | Регион | Код | Регион | Код |
  | --- | --- | --- | --- |
  | Москва | `7700000000` | Санкт-Петербург | `7800000000` |
  | Московская область | `5000000000` | Новосибирская область | `5400000000` |
  | Краснодарский край | `2300000000` | Свердловская область | `6600000000` |
  | Татарстан | `1600000000` | Челябинская область | `7400000000` |
  | Нижегородская область | `5200000000` | Самарская область | `6300000000` |
  | Ростовская область | `6100000000` | Красноярский край | `2400000000` |
- `minSalary` сверяется с верхней границей вилки, поэтому «от 60 000 до 200 000» проходит порог 100 000.
  Вакансии вообще без указанной зарплаты не отбрасываются — для этого включите `requireSalary`.
- `excludeKeywords` ищутся и в названии, и в описании, без учёта регистра.
- `maxNotificationsPerRun` защищает от простыни на сотню сообщений при первом запуске.

Расписание меняется в cron-выражении внутри `job-radar.yml`.

## Как работает дедупликация

`state/state.json` хранит id отправленных вакансий (последние 3000) и время прошлого запуска.
Следующий запуск запрашивает вакансии, изменённые с прошлого раза минус шесть часов нахлёста:
данные попадают в API с задержкой, и без нахлёста часть вакансий терялась бы. Повторы,
которые из-за этого приходят, отсекаются по списку id.

Состояние сохраняется только после успешной отправки. Если Telegram недоступен, запуск падает
с ошибкой и ничего не запоминает — те же вакансии придут в следующий раз. Выбор сделан
в пользу возможного дубля, а не потери: если дайджест разбился на несколько сообщений
и упало второе, при повторе придёт весь дайджест целиком.

С откликами противоположный приоритет: там дубль хуже пропуска, потому что повторное письмо
работодателю выглядит навязчиво. Поэтому команды подтверждаются в Telegram **до** выполнения,
журнал откликов пишется на диск сразу после отправки, а шаг коммита состояния в workflow
выполняется даже если поиск вакансий потом упал.

## Что защищает от ошибок

Бот выполняет команды только из вашего чата. Любой может найти бота и написать ему, но
сообщения с чужим `chat_id` отбрасываются — иначе посторонний мог бы отправлять письма
от вашего имени.

Перед отправкой отклик проверяется: код вакансии существует, адрес есть, письмо не пустое
и не короче 30 символов, отклик на эту вакансию ещё не отправлялся. Ограничение на длину —
защита от случайной отправки полупустого письма, которое читается как спам.

Текст письма пишете вы. Автогенерации шаблонов здесь нет намеренно: рассылка однотипных
писем по всем адресам подряд портит впечатление у тех самых работодателей и быстро упирается
в суточные лимиты почтового провайдера.
