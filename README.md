# Job Radar

Мониторинг новых вакансий с уведомлениями в Telegram. Раз в два часа опрашивает открытое API
«Работа в России», отбирает подходящее по зарплате и стоп-словам, отбрасывает уже виденное
и присылает дайджест в чат.

Работает без сервера и без платных подписок: расписание держит GitHub Actions, состояние
хранится в самом репозитории. Тот же сценарий продублирован как workflow для n8n.

![тесты](https://img.shields.io/badge/tests-48%20passing-brightgreen)

## Зачем

Открывать сайты вакансий каждый день — рутина, а хорошие предложения закрываются за пару суток.
Радар делает это сам и присылает только то, что раньше не показывал.

## Что внутри

| Файл | Роль |
| --- | --- |
| `src/index.js` | точка входа: собирает запросы, фильтрует, отправляет |
| `src/sources/trudvsem.js` | доступ к API с постраничной выборкой и повторами при сбоях |
| `src/filter.js` | правила отбора, дедупликация, сортировка |
| `src/telegram.js` | форматирование дайджеста и отправка в Bot API |
| `src/state.js` | история отправленного и окно поиска между запусками |
| `.github/workflows/job-radar.yml` | запуск по расписанию |
| `n8n/job-radar.workflow.json` | тот же сценарий для n8n |

Источник — [opendata.trudvsem.ru](https://opendata.trudvsem.ru), государственный портал «Работа
в России». Выбран потому, что не требует ни ключа, ни регистрации, ни одобрения приложения:
hh.ru закрыл поиск вакансий за OAuth и отдаёт `403` анонимным клиентам.

## Как запустить локально

Нужен Node.js 20 или новее, зависимостей нет.

```bash
npm test              # 48 тестов
npm run dry-run       # показать найденное в консоли, ничего не отправляя
```

Для реальной отправки понадобятся токен бота и id чата:

```bash
export TELEGRAM_BOT_TOKEN="123456:ABC..."
export TELEGRAM_CHAT_ID="123456789"
npm start
```

## Подключение Telegram-бота

1. Напишите [@BotFather](https://t.me/BotFather), отправьте `/newbot` и следуйте подсказкам.
   В ответ придёт токен вида `123456:ABC-DEF...`.
2. Напишите своему боту любое сообщение — без этого он не имеет права писать вам первым.
3. Узнайте id чата: откройте `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
   и найдите `"chat":{"id":...}`.

Токен — это пароль от бота. Держите его в секретах GitHub или переменных окружения,
никогда не коммитьте в код.

## Запуск по расписанию в GitHub Actions

1. Создайте репозиторий и загрузите в него проект.
2. В настройках репозитория откройте **Settings → Secrets and variables → Actions**
   и добавьте два секрета: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
3. Разрешите workflow писать в репозиторий: **Settings → Actions → General →
   Workflow permissions → Read and write permissions**. Это нужно, чтобы радар
   коммитил `state/state.json` и не присылал одни и те же вакансии повторно.
4. На вкладке **Actions** выберите **Job Radar → Run workflow**. Для первой
   проверки поставьте галочку `dry_run` — вакансии появятся в логе без отправки в чат.

Дальше запуск идёт сам по cron. Расписание в `job-radar.yml` задано в UTC:
`0 4,6,8,...` соответствует 07:00, 09:00 и далее по Москве.

GitHub может отключить cron в репозитории, где 60 дней не было активности — достаточно
зайти и запустить workflow вручную. Также cron на бесплатном тарифе иногда стартует
с задержкой в несколько минут, для этой задачи это неважно.

## Вариант на n8n

Файл `n8n/job-radar.workflow.json` импортируется через **Workflows → Import from File**
и повторяет ту же логику из пяти нод: расписание → сборка запросов → HTTP-запрос →
отбор и оформление → отправка в Telegram.

Токен и id чата берутся из переменных окружения n8n — задайте `TELEGRAM_BOT_TOKEN`
и `TELEGRAM_CHAT_ID` перед запуском. В self-hosted n8n доступ к `$env` из выражений
включается переменной `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`. Если правило запрещено
политикой вашей установки, замените в ноде «Отправить в Telegram» подстановку `$env`
на обычные Telegram-креды n8n.

Историю отправленного n8n держит в `$getWorkflowStaticData('global')`, поэтому файл
состояния здесь не нужен.

Логика нод покрыта тестами (`test/n8n-workflow.test.js`): они исполняют код прямо из JSON
workflow, так что версия для n8n не может разойтись с версией для Actions незамеченной.

## Настройка под себя

Всё, что меняется без правки кода, лежит в `config.json`:

```json
{
  "queries": [{ "text": "python", "region": "7700000000" }],
  "filters": {
    "minSalary": 80000,
    "excludeKeywords": ["вахта", "курьер"],
    "requireSalary": false,
    "maxAgeDays": 3
  },
  "limits": { "perQuery": 100, "maxNotificationsPerRun": 12 }
}
```

- `queries` — поисковые запросы; `region` можно не указывать, тогда поиск идёт по всей стране.
  Код региона — это код ОКТМО: две цифры региона и восемь нулей. Проверенные значения:

  | Регион | Код | Регион | Код |
  | --- | --- | --- | --- |
  | Москва | `7700000000` | Санкт-Петербург | `7800000000` |
  | Московская область | `5000000000` | Новосибирская область | `5400000000` |
  | Краснодарский край | `2300000000` | Свердловская область | `6600000000` |
  | Татарстан | `1600000000` | Челябинская область | `7400000000` |
  | Нижегородская область | `5200000000` | Самарская область | `6300000000` |
  | Ростовская область | `6100000000` | Красноярский край | `2400000000` |
- `minSalary` сверяется с верхней границей вилки, поэтому «от 60 000 до 200 000» проходит порог 100 000.
  Вакансии вообще без указанной зарплаты не отбрасываются — для этого включите `requireSalary`.
- `excludeKeywords` ищутся и в названии, и в описании, без учёта регистра.
- `maxNotificationsPerRun` защищает от простыни на сотню сообщений при первом запуске.

Расписание меняется в cron-выражении внутри `job-radar.yml`.

## Как работает дедупликация

`state/state.json` хранит id отправленных вакансий (последние 3000) и время прошлого запуска.
Следующий запуск запрашивает вакансии, изменённые с прошлого раза минус шесть часов нахлёста:
данные попадают в API с задержкой, и без нахлёста часть вакансий терялась бы. Повторы,
которые из-за этого приходят, отсекаются по списку id.
